# Virtual-8086 mode on Machine

Design and implementation record for xj-srh.37, originally audited against
`d8bf798e` (paging step 5). Public V86 admission is implemented as of
`0bc16f55` (step 4); §11 records step-5 acceptance witnesses and census results.
The insertion-point audits in §§3, 10 describe earlier snapshots, including
their superseded public refusals. The contract describes support for a
protected-mode operating system running real-mode programs on `CpuModel::I80386`,
`I80486Dx`, and `I80486DxCpuid`. All three stay interpreted. The 80286 has no
V86 mode. VME, CR4, software-interrupt redirection, VIF/VIP, and later processor
facilities are outside this proposal.

**Hardware** below is sourced behavior. **Proposed** and **ASSUMED** distinguish
engine choices from that behavior. The original recommendations are collected
in §8 and the maintainer's accepted decisions in §9.

## 2. Hardware contract

### 2.1 Regime, addresses, and segments

V86 is protected execution with CR0.PE=1 and EFLAGS.VM=1. CPL is always **3**,
independent of the low bits of the visible CS value. VM is loaded by a task
switch to a 32-bit TSS or by CPL-0 IRETD from a VM=1 stack image. POPFD cannot
set it (SDM Vol. 3B §§23.2.1, 23.2.4–23.2.5 pp. 23-6–23-9; 386 PRM
§§15.2.2–15.3 pp. 15-4–6; 486 PRM §§23.2.2–23.3.1 pp. 23-5–6).

All six segment values are real-style paragraph numbers: base=`u32(selector)<<4`,
limit=`FFFFh`, default operand/address size 16, stack address size 16. Loading
zero is valid, including SS and CS. No GDT/LDT lookup, selector privilege check,
presence check, or accessed-bit update accompanies a V86 segment load. MOV/POP
segment, LDS/LES/LFS/LGS/LSS and far control transfers must all use this rule.
Operand/address overrides permit 32-bit operations and effective offsets, but
do not lift the 64-KiB limit. Check the whole operand: an offset above FFFFh or
an operand crossing the limit faults (#SS(0) for SS, #GP(0) otherwise); do not
wrap the operand's bytes at 64 KiB (386 PRM §§15.1.1–15.1.2 pp. 15-1–3,
§15.6 items 7–8 p. 15-11; 486 PRM §§23.1.1–23.1.2 pp. 23-1–3; SDM Vol. 3B
§23.2 p. 23-5 incorporates §23.1.1 pp. 23-1–2; Vol. 2A BOUND p. 3-106).

The linear sum can reach `10FFEFh`; V86 does not itself truncate it at 1 MiB.
Paging may map those linear pages anywhere in 32-bit physical space or alias
the high 64 KiB onto low pages. V86 fetches and explicit data/stack accesses
are **user** accesses: supervisor-only pages are inaccessible regardless of
IOPL (SDM Vol. 3B §§23.2.3–23.2.4 pp. 23-7–8; 386 PRM §§15.1.2, 15.2.1–2
pp. 15-3–4; 486 PRM §§23.1.2, 23.2.1–2 pp. 23-2–5).

**Proposed integration:** retain the existing Machine address chain:
effective offset → V86 limit check → segment-base addition → optional paging
→ physical bus width/A20 → memory/device access. A20 is the existing board
input, not an implicit VM-bit wrap rule. In particular, do not clear linear bit
20 before a page walk. Apply the existing bus gate to page-table and operand
physical accesses; high-linear/low-physical aliases and physical SMC tracking
remain the paging implementation's responsibility (the accepted
[paging design](paging.md) §§3–4 and decision-22).

The six sensitive families are CLI, STI, PUSHF, POPF, INT n, IRET. LAHF, SAHF,
PUSH/POP general or segment registers, RET/RETF, CLC/STC/CMC, CLD/STD and
legal LOCKed instructions acquire no additional IOPL test (SDM Vol. 3B §23.2.7
p. 23-10; historical lists and the LOCK conflict in §1). This does not exempt
them from their operand, opcode, or segment-limit faults.

IN, OUT, INS, OUTS instead consult the **current TSS I/O permission bitmap
regardless of IOPL**, including 3. All bytes of the transfer must be allowed;
missing bitmap bytes deny access with #GP(0). A 16-bit TSS supplies no bitmap.
Read the live base at TSS+66h, not a stale task-switch snapshot. REP with a zero
count executes no I/O and makes no bitmap check (SDM Vol. 3B §23.2.8.1 p. 23-11;
Vol. 1 §20.5.2 pp. 20-4–5; Vol. 2A IN p. 3-455, INS pp. 3-464–465; Vol. 2B OUT
p. 4-171, OUTS pp. 4-173–175, REP p. 4-564; 386 PRM §15.5.1 p. 15-9,
§17.2.2.5 p. 17-15; 486 PRM §§23.5.1, 8.3.2 pp. 23-10, 8-7–8).

The protected-only #UD list is exhaustive for the existing historical
descriptor-query/task-register families. Ordinary far CALL/JMP/RETF in V86 use
paragraph addressing; their operand bits cannot name a protected call gate or
TSS. Protected code or an IDT task gate initiates task transfers instead
(386 PRM §§15.1.2, 15.3 pp. 15-2–6; 486 PRM §§23.1.2, 23.3 pp. 23-2–6).

One-byte **INT3 (`CC`)** and **INTO (`CE`, when OF=1)** bypass the INT n IOPL
test, but still check the IDT gate DPL as software events. INTO with OF=0 falls
through. `CD 03` remains an IOPL-sensitive INT n. A failing BOUND is #BR, a
**fault**, ignores gate DPL and saves the BOUND address; it is neither an INT n
nor a software trap. Other processor exceptions, IRQs and NMI ignore gate DPL
and enter through the protected IDT (SDM Vol. 2A INT pp. 3-467–471, BOUND
pp. 3-105–106; Vol. 3B §23.3.1 p. 23-12). Retain the existing INT1/decode
policy; this note adds no undocumented instruction support.

### 2.4 486 and x87 differences

The V86 entry, segment, IOPL and bitmap rules are shared by all three models.
Both 486 entries retain their existing ISA/flag catalogue differences: AC is
writable; ID and CPUID are available only on `I80486DxCpuid`; BSWAP, XADD and
CMPXCHG remain 486 instructions in V86 as well (486 PRM §23.1.1 pp. 23-1–2;
decision-23's 486 amendment supplies the identity-source audit). No VME/CR4
facility follows from CPUID availability.

486 alignment checking can apply in V86 because CPL=3 (SDM Vol. 3A §7.15,
Alignment Check exception p. 7-53; 486 PRM §4.1.3 p. 4-7). **Implemented boundary:** keep
the existing `LegacyAlignmentCheck` refusal for AM=AC=1, even on aligned or
register-only instructions, until the separate #AC work replaces it. State
this limitation in support claims and the census. Do not synthesize #AC or
clear AC to make V86 execute. I80386 continues fixing AC/ID to zero.

Use the attached x87 and current EM/TS/MP gates; a V86 task switch sets TS as
other task switches do. #NM and internally routed #MF are CPU exceptions and
take the V86 protected-delivery path. V86 has **real-address x87 environment
formats** despite PE=1: preserve the independently selected 14/28-byte
environment and 94/108-byte save sizes and real-format pointer packing (SDM
Vol. 1 §8.1.10 pp. 8-11–12, Figs. 8-9–8-12; 486 PRM §15.1.6 pp. 15-8–10).
Do not reuse `regime == Protected` or raw PE as a complete x87 format predicate.

External numeric-error routing is a separate CPU/board contract. Preserve
I80386's `NumericErrorRoute::External`: an assertion notification retires no
additional instruction, a waiting numeric instruction remains unretired, and
the embedder may inject the board's chosen IRQ, which then enters the V86
protected IDT normally. A board acknowledgement is not an x87 status clear.
The hardware direct-error path is vector 16 (386 PRM §§11.1.2, 11.1.5.3
pp. 11-1, 11-4; §15.6 items 14–16 p. 15-12). External wiring and handoff
semantics are engine/board choices in [fpu-error-routing.md](fpu-error-routing.md).

On the 486, NE=1 selects native #MF; NE=0 selects the FERR#/IGNNE# external
mechanism (486 PRM §§4.1.3, 19.2.2, 19.2.4 pp. 4-7, 19-2, 19-4). The audited
engine retains NE but has not implemented that route and disallows selecting
External on the 486 entries. V86 retains that documented limitation, including
internal #MF with NE=0 (witnessed in §11);
its implementation must not claim to complete 486 external-error routing or
reinterpret IOPL as numeric-error policy.

## 4. Proposed implementation seams

### 4.1 Context and segment class

Add `MachineRegime::Virtual8086` beside Real/Protected. It is an execution
regime, not a new CPU model or Application `CpuMode`. Derive it once from
model capability, PE and VM; force CPL=3 and all three default widths to 16.
Reject invalid public images (VM on an unsupported model, VM with PE=0,
inconsistent CPL/caches) with a typed context error, rather than interpreting
them as some other mode. Guest transitions construct coherent images.

Always choose **SegmentClass::Checked**, with or without PG. V86's paragraph
arithmetic resembles Direct but its privilege guards, checked fetch/limits,
IDT delivery and optional paging do not satisfy Direct's current contract.
It must not share an Application Real16 or ordinary real-mode block.
Paged V86 nevertheless shares ordinary multi-instruction blocks in this
class, with live V86 operands and in-block segment loads; sensitive
instructions stay singletons (spec.md §17.10, xj-to9.18).

Introduce one V86 segment-install helper that sets selector, base, FFFFh
limit, usable state and 16-bit size attributes for every load. Attributes are
internal canonical labels, **ASSUMED**, not GDT descriptor contents. A V86
access personality checks bounds but permits reads/writes through all segment
overrides as real-style addressing requires; never interpret label DPL or
visible selector RPL as permission. Do not call the retained-cache 386
`reload_real`. VM exit installs protected CS/SS and null/unusable data caches.

Audit predicates by purpose: descriptor-based segmentation applies only to
Protected; IDT delivery and PE-dependent system services apply to Protected
**and V86**; real x87 formats apply to Real **and V86**. An indiscriminate
replacement of `== Protected` by `!= Real` gets these wrong. Cover scalar,
string/REP, stack/ENTER, x87, fetch, far transfers and segment reload paths.

### 4.2 Entering and executing IRET

At protected CPL 0, with NT=0, dword IRET reads the initial EIP/CS/EFLAGS,
then recognizes VM=1 **before** protected CS/SS descriptor or outward-ring
checks. Validate the old stack's complete 36-byte frame, read all nine dwords,
and validate target EIP≤FFFFh before committing registers/flags/caches. Slots
from the old stack pointer upward are:

| Byte offset | Image |
|---|---|
| +00h / +04h / +08h | EIP / CS / EFLAGS |
| +0Ch / +10h | ESP / SS |
| +14h / +18h / +1Ch / +20h | ES / DS / FS / GS |

Load selectors from low 16 bits, full ESP from its slot; subsequent V86 stack
addressing uses SP. Install fresh V86 caches, CPL=3 and model-filtered EFLAGS
including VM/IOPL/RF. Preserve RF at completion. No TSS access is needed for
this IRET entry itself. The current TSS becomes relevant on delivery or I/O.
The old protected stack may independently have SS.B=0 or 1.

If old CPL>0, ignore attempted VM modification and use existing protected
return checks. Word IRET cannot enter V86. Protected NT=1 takes the existing
task-return path first; a target TSS may then enter V86. Conversely, an IRET
**already in V86** first passes its IOPL guard, reads a three-slot real-style
frame and remains V86, even with NT set. Do not let its NT bit route into
`CheckTaskReturn`'s protected backlink operation. These are distinct IRET
personalities under SDM Vol. 2A pp. 3-491–493.

Keep faultable reads in temporaries. MMIO handoffs preserve the exact frame
reads already answered and their identities. An unanswered read or #PF leaves
the return instruction unretired and its architectural destination state
uncommitted, subject to existing page A/D effects. Reuse current retry and
page-transaction limits, with typed refusal before exceeding them.

### 4.3 Interrupt/exception exit through gates

Explicitly route V86 to protected-IDT dispatch. Keep IDT bounds, gate DPL for
software events, presence, target selector and descriptor checks. Require a
32-bit interrupt/trap gate targeting **nonconforming DPL=0 code** for this
supported path; a nonzero-DPL or conforming target is #GP(target selector),
with the existing EXT policy. A task gate uses §4.4 instead. A 16-bit gate has
the proposed conservative refusal from §1, not silently a normal five-slot
privilege transition.

Use the current TSS's ring-0 stack slot. For a 32-bit TSS this is ESP0 at +04h
and SS0 at +08h. SDM Vol. 2A INT p. 3-476 also specifies a current 16-bit TSS:
SP0 at +02h and SS0 at +04h, zero-extended into the new pointer. **Proposed:**
retain that existing `inner_stack` capability for IRET-created V86 contexts;
requiring a 32-bit *incoming V86 task image* does not itself require a 32-bit
current TSS for stack IRET. Preserve new SS.B's independent stack-pointer
arithmetic. Do not make TR validity a prerequisite for executing every V86
instruction; check it when the operation needs it.

Reserve and preflight **36 bytes**, or **40** when an error code is pushed,
on the ring-0 stack. Push in this order, using dword slots:

`GS, FS, DS, ES, old SS, old ESP, EFLAGS, CS, saved EIP, [error code]`.

Thus a no-error frame starting at the handler's ESP has exactly the layout
that §4.2 consumes. Save full old ESP, not only SP. Selector-slot high halves
are zero as an **ASSUMED** deterministic padding policy matching existing
Machine pushes; tests must distinguish that choice from the architectural
low-word values. Save VM=1 in the frame and set saved RF for faults under the
existing fault-frame rule. After successful frame construction, install
protected CS/SS, CPL=0; clear live VM, NT, RF, TF; clear IF for an interrupt
gate and preserve IF for a trap gate. Null **GS/FS/DS/ES**, including unusable
protected caches. Never zero CS/SS as a literal reading of historical “all
segment registers” might imply (SDM Vol. 3B §23.3.1.1 pp. 23-12–13,
Fig. 23-4; Vol. 2A INT pp. 3-475–477; 386 PRM Fig. 15-3 p. 15-7; 486 PRM
Fig. 23-3 pp. 23-7–8).

All descriptor/TSS/new-stack accesses use the supervisor adapter, even while
the old code is V86 CPL 3. Reads of the old V86 program's explicit operands
remain user accesses. Preserve paging fault provenance, CR2, A/D effects and
the current descriptor accessed-bit/ROM/device boundaries. A failed delivery
feeds existing serial-fault/#DF/shutdown logic; do not fall back to the IVT.
Keep the existing INT check order where compatible, with the additional V86
target checks and enlarged stack bound. Record any underdetermined ordering
as ASSUMED, following the privilege-transitions note.

### 4.4 Task switches

Reuse `SwitchState` and the existing committed-task boundary, busy/backlink
operations, NT cause rules, CR3 load, TS and LDTR handling. A 32-bit incoming
TSS with VM=1 selects CPL=3 regardless of CS.RPL and installs all six V86
segments without descriptor validation. Load VM before interpreting segment
images. The LDT remains system state and follows the existing task-load
checks; it is not used to interpret those six paragraph numbers. Check EIP
against FFFFh in the incoming context. Preserve the existing task-debug
T-bit completion refusal until its separate support lands.

Task-gate exit saves live V86 EFLAGS and selectors in the outgoing TSS;
it does **not** push the nine-slot interrupt frame or perform the gate-path
data-segment nulling. The target task's image installs its own segments/flags;
normal VM=0 handlers become protected code. An exception's error-code push
belongs to the incoming task under the existing task-gate contract. A handler
with NT=1 returns through the backlink; VM=1 in that 32-bit target TSS restores
V86. A 16-bit incoming TSS clears the high flags, including VM (SDM Vol. 3B
§§23.2.5, 23.3.1.3 pp. 23-8–9, 23-14; 386 PRM §15.3.1 p. 15-6;
486 PRM §23.3.1 p. 23-6).

Do not “clear VM to exit” on a task gate before saving the old task. Do not
roll back a switch that has committed if LDTR, incoming EIP, error push or
another later operation faults. Preserve reached-task fault placement,
accepted-event ownership, task/page continuations and exact-once retirement
from [task-switches.md](task-switches.md) and decision-24. Add a V86 segment
installation stage or branch to that state machine, not a second switcher.

### 4.5 One privilege policy, shared I/O

Extend the existing lift-time privilege classification in `privilege_guard`
to accept the regime. For V86, emit the live IOPL=3 guard for the six sensitive
families before any stack/operand effect. Emit CPL-0 failures for valid
privileged forms, and emit the protected-only #UD forms before that generic
classification. Existing `PrivilegeCheck::Iopl` suffices with canonical CPL=3;
keep the required policy in one classifier rather than six handler-local
tests. Do not specialize on the current IOPL at lift time: flags can change
at runtime and the guard's semantics must remain explicit.

For port guards, separate “bypass permitted” from “bitmap permitted.” Protected
execution keeps CPL≤IOPL bypass; V86 bypass is false. REP-zero bypass stays
true independently. Reuse the same live-TSS bitmap reader and supervisor
access, then the existing IN/OUT exits and INS/OUTS continuations. A denied
bitmap must precede an observable port transfer. In a permitted INS, retain an
already supplied port value while a faultable destination store is resumed;
never request input again. Recheck the appropriate live permissions at the
existing instruction/iteration boundaries without changing REP accounting or
promising asynchronous bitmap snooping beyond the established contract.

## 5. Integration contracts

### Delivery policy, log and accounting

`ExceptionDelivery::Outward` continues returning an architectural exception
with the V86 instruction/state and fault metadata; it does not secretly enter
the ring-0 monitor. `InGuest` uses the protected delivery just specified.
Neither option turns CPU faults into unsupported-operation refusals. External
IRQ/NMI and software interrupt behavior follow the existing distinction
between exception reporting and event delivery.

Record one delivery-log entry only when its handler/task has actually been
entered. Preserve the original V86 CS, CS base, saved IP, CPL=3, full ESP and
segments across frame/device retries; the destination CPL normally becomes 0.
The record's saved linear address is the pre-paging, pre-A20 CS-base sum, not
the handler address or translated physical address. Task-gate logs keep the
outgoing origin even after the task commit changes `cpu`.

**Proposed:** append `virtual_8086_before` and `virtual_8086_after` booleans to
the non-exhaustive `DeliveryRecord`. Capture the former with `Origin`/pending
event state at acceptance, including a task gate; derive the latter at
completion. Keep `DeliveryRegs.flags`'s documented PUSHFD-compatible VM/RF
mask. No snapshot option should be necessary to identify the regime. Keep
diagnostics outside CpuState, cache keys and checkpoints, and preserve the
disabled-log fast path. IRET is not a delivery and creates no log entry.

Successful instructions, including IRET/IRETD and software INT3/taken INTO,
retire once. A successful INT n at IOPL=3 retires once; an INT n intercepted by
#GP at IOPL<3 retires zero. BOUND/#UD/#GP faults retire zero and save the
faulting IP; software traps save the following IP. IRQ/NMI delivery and
numeric-error notifications retire no instruction. A completing delivery is
not an extra guest step, but continues to participate in the delivery-stall
limit. Keep TF/RF, STI/SS shadows, NMI blocking/unblocking and priority under
the current Machine boundary logic. In particular, IRET's existing NMI
unblocking on an attempted return must survive the new early IOPL-fault path
(SDM Vol. 2A IRET pp. 3-490–491).

Zero-budget probes must not consume a continuation or completion input.
Split-budget runs, port/MMIO answers, and accepted events must neither retire
twice nor lose an IRQ. A change in VM at a completed transfer ends the old
block and refreshes context before fetching another instruction. No pending
event may run in a half-installed V86 image.

### Cache, state and checkpoint shape

Keep V86 in private Checked keys; the existing regime field and VM-bearing
context stamp already provide the needed separation once the new regime is
derived. Use the same linear-fetch and paged physical-source validation as
other Checked contexts. Retain context round trips, but prove that real and
V86 code at identical CS:IP/linear addresses never share IR. Model semantics
identity must reflect changed Machine lowering without changing unrelated
Application identities. Do not add a per-instruction cache lookup or VM test
to Direct execution.

VM, selectors, hidden caches, CPL, CR0/CR3, x87 and numeric-error state already
exist in CpuState. **Proposed:** add no architectural field. Derive the regime
instead of maintaining a second mutable `is_v86`. If an unavoidable new
CpuState field emerges, append it and pin all existing `#[repr(C)]`/JIT ABI
offsets; never reorder or repurpose reserved storage. Private Vcpu delivery
and task-continuation structures can carry their origin/mode state.

A boundary checkpoint must restore VM and coherent canonical caches/CPL,
model/FPU identity, flags including model-specific AC/ID, paging controls,
physical RAM/tables and board/device state. After `reset_execution_state`,
derive V86 anew and discard translation/context assumptions; an equal-byte
restore still cannot preserve stale physical fetch proofs. Keep the existing
support boundary: copying CpuState/forking with a pending Machine
mid-instruction continuation is unsupported (decision-24). Do not imply that
a raw CpuState copy serializes Vcpu task/page/event continuations. Delivery
logs retain their existing independent timeline after restore.

### Performance acceptance

Resolve the VM personality at context derivation/lift and cold transfer
helpers. Add no V86 check to the shared scalar hot loop, ordinary Direct
memory accesses, or real/protected op streams that do not need a different
operation. Reuse current paging and boundary specialization. This is a design
target; measurements, not source shape, establish the result.

Every implementation step touching shared lowering/IR/walk/dispatch must run
decision-23's accepted **two-profile +0.5% gate**: `scripts/perf-campaign.sh`,
default release and `perf`, against a named main baseline; each real16_loops
cell and store-probe cell blocks if it exceeds +0.5% in **both** profiles.
Single-profile misses are reported as drift; preserve its process protocol,
like-mode bimodal fallback, equal step/retired counts, and separately reported
means. Retain the established wall-time and Machine/alias gates too. Add a
focused unchanged protected-mode loop comparison because Real16 campaigns
alone cannot show the cost on that path. New V86 throughput is reported,
never traded for a regression on existing paths. See decision-23, “Measurement
protocol and two-profile gate,” and [commands.md](../commands.md).
