## Tiering — wall-clock by mode

`eager` compiles every block on first execution; `tier` interprets a block until it is hot (50 runs) then compiles it inline; `bg` compiles hot blocks on a worker thread (`x86jit-run` ships `tier`); `region-bg` (BGT-6, opt-in) tiers a hot loop up to a background-compiled superblock region — a win only on long multi-block warm loops (`hotloop`), a loss on one-shot workloads. `best↓` is the fastest mode's speedup over `eager`.

Eight rounds per workload, four paths interleaved in rotating order. Every path
occupies each position twice. Each sample uses a fresh VM and vCPU, followed by
warm-up outside both measurement windows. The divisor is 5: warm-up is 200,000
steps, except `straight-line`, which always warms one full 30,592-step traversal
and measures three more (91,776 steps). VM construction, program/data loading,
cache fillers, state comparisons and reporting are excluded. The counter window
includes the two clock reads and counter-call overhead; no overhead is subtracted.
Wall time brackets only the measured step runner. All paths use the same runner.

`Application` is today's `set_cpu_mode(CpuMode::Real16)` path (the future alias).

A20 enabled. `I286 A20 off` also calls `Vcpu::set_a20_enabled(false)`. Ordinary
hidden segment caches are seeded with `CpuState::legacy_real_entry` after setting
the selectors; changing visible selectors alone does not configure those caches.
Code, data and stack addresses stay below 1 MiB on every workload.

Every sample asserts budget exhaustion and its exact returned step count. Warm-up
and measured `retired_instructions()` counts, and final GPRs, IP, six segment

passed. The denominator is a `run_steps` guest unit: one completed instruction or

## Direct class for Machine real mode (decision-23 U2)

This record covers U2 rebased onto `fd67927`: the I286 empty coprocessor socket
and hardware task switches. The alias reference is the provided release build
of `fd67927` with the current benchmark harness. The Machine change control is
the accepted rebased `0bdb7a4` build. U2 uses amended decision-23 §5: Machine
within +2% of Application for loops of at least 64 steps per call; every alias
loop must remain within +0.5% of the parent. `ip-boundary-1` is reported and its
Machine/alias gate remains assigned to U5. The dispatchers remain separate.

### Design and correctness

`MachineContext::segment_class` is Direct only with PE clear, no reset-fetch marker,
and six usable ordinary caches: selector-derived bases, FFFFh limits, CS attributes
9Bh and data attributes 93h. Other caches, big real mode, protected mode and reset
fetch use Checked. Direct uses shared-cache multi-instruction blocks, the common
scalar lifter and interpreter walk with Machine specialization. Generation and
width validation remains at lift time; unsupported shared forms retain the
Machine lowering. TF and architectural boundaries cap execution appropriately.

Direct keys include the Machine namespace and A20 assumption; hits validate decode
IP and context. A20-on blocks have no per-access mask. A20-off uses that memory
view where all selectors are at most F000h; upper-segment execution retains the
bus-gated, split instruction lowering. The measured loops are below 1 MiB and do
not establish shared-block speed for wrapping upper-segment accesses.

SMC invalidations select retained Checked instruction IR through a bounded
sixteen-page hint. Nearby data writes that invalidate no translations remain
shared. Source watches, publication generations, fetch permits and retained-byte
validation remain authoritative; the hint never validates code.

The paired witnesses retain whole-operand stack limits and SP addressing,
32-bit control-target checks, entry EIP validation, generation-specific vectors,
scalar MMIO RMW completion, distinct same-address string reads, source-first
Machine string fault ordering, first-missing-byte integer stores and complete
fault evidence. Segment-limit stores/RMWs retain Write intent; FP stores keep
their preflight transfer-base reporting. `PROVENANCE.md` §3 records the manuals'
silence on observable source-MMIO versus destination-limit priority. Application
string ordering and the frozen Real16 IR remain unchanged.

The parity harness compares complete exits and metadata, registers, RAM, hidden
segment/system state, x87/vector state, steps and retirement. Only private retry
identity and its deliberate unused ES attribute are normalized. ES=92h forces
Checked only while ES is not reloaded. Coverage includes RAM/Trap strings with
and without REP, I386 66h/67h forms, XLAT, far transfers, A20 wraps, stack/frame
aliases and both MMIO acknowledgments.

Task continuations retain their stage-based transfers and stay Checked. They
block Direct execution and new event acceptance. Ownership abandonment precedes
entry validation. Direct entry clears stale task completion flags; shared blocks
cannot start a task switch, and Checked transitions clear flags before returning
to Direct. The I286 first unavailable opcode byte retains priority over a later ESC MSW gate.
The verifier combines valid segment-class contexts with fourteen system-op probes;
protected-only slots remain unseen in Direct contexts. No CpuState/jit_abi fields
or frozen snapshots changed in this performance repair.

### Measured alias cost and repair

The task-switch ownership and continuation code is confined to Machine execution;
it does not run in the Application benchmark path. Relative to the parent, the
Application VM file had one change: forced inlining of `finish_single`, retained
from the earlier SMC repair. In the rebased build this enlarged the Application
resolver frame from 0x2A0 to 0x2E0 bytes and added cache-hit spill work.

Serial source bisections measured the alternatives against the supplied parent
and `0bdb7a4`, using six samples per side with divisor 5. Removing only forced
materializer inlining saved about four host instructions per block and fixed the
steady-loop failures, but left SMC-next-64 close to +0.5%. Moving all source
ownership off cache hits made the alias much faster, but exceeded the Machine/alias
gate and is not included. The final change preserves the parent's source-ownership
scope and outlines only Real16 lifting/publication into `resolve_real16_uncached`.
The materializer can still inline inside that cold frame; cached execution does
not carry its lifted IR, backend alternatives or publication drop guards.
All source watches, generation checks, fetch permits and cancellation paths remain.

The first cold-helper-only campaign passed every alias gate but left the rebased
Machine boundary loop about +4.03% above the alias. Machine dispatch repeated the
same continuation-state checks and reset stale task-completion flags on every
shared block. The final repair snapshots task state once per dispatch iteration,
reads saved TF only for an existing continuation, and clears stale completion
flags once at Direct run entry. Event delivery restarts the iteration; port-input
completion cannot change task state. Ownership validation remains before entry
validation, pending tasks stay Checked, and event inhibition remains unchanged.
These changes keep bookkeeping at block and run boundaries in the existing dispatcher.

### Measurement method

Measured on 2026-11-12, 14:22:54–14:28:25 UTC.
Release/default-feature builds use the same host and rustc/SDK as the parent;
both builds use the same empty Rust flag set. The supplied parent binary was not
rebuilt. Five serial parent/candidate pairs alternate order AB/BA for `call-ret`,
`alu`, `dos-mixed`, `smc-next-64` and `data-next-to-code`. Each invocation uses
`real16_loops 5 3 <workload>`: fifteen samples per side and path. The other ten
workloads use three serial rounds per engine with divisor 5. An earlier divisor-1
parent ALU invocation reached the 180-second deadline under host load. The final
campaign uses divisor 5 consistently and retains every completed sample.
This parent/candidate campaign contains 1,050 samples across the five paths.

A separate interleaved three-round `0bdb7a4`/candidate comparison covers all fifteen
workloads and four Machine configurations, with divisor 5. SMC-next-1 is repeated
in five interleaved pairs (fifteen samples per side) to resolve its small upward
median. That repeated cohort replaces its initial three-sample control row.
Medians and full min–max ranges are reported without trimming. Every sample checks registers, step and
retirement parity; warm-up is excluded. No build or test ran alongside a benchmark
in this session. The host had other activity; wall time is informational.
Every cargo command used the bounded host-lock wait and at most four build jobs.

## Unified lowering (decision-23 U3)

### Design and scope — READ

`lift/legacy.rs` supplies one lowering for alias Real16 and Machine 16/32-bit stack, control,
flag-image, frame, far-pointer, segment-register, BOUND and XLAT instructions. Operand size comes
from the instruction; address and stack sizes come from the context. Scalar stack/near transfers
emit scalar IR; frame and segment operations use shared sized helper IR. Direct addresses inline
selector bases and constant limit/vector rules; Checked uses retained segment checks. Machine
applies A20 through its existing route; the alias ignores A20 and caches. Its helper adapter
supplies the frozen context and restores inert retained state.

Retired: `lift_call_real16`, `lift_ret_real16`, `lift_far_jmp_real16`, `lift_far_call_real16`,
`lift_retf_real16`, `lift_loop_real16`, `lift_load_far_ptr_real16`, `lift_leave_real16`,
`lift_bound_real16`, `lift_xlat_real16`, `lift_mov_sreg_real16`, the Real16 stack/flag/frame match
arms, and `specialize_shared_stacks`. Ordinary `lift_push`/`lift_pop` still serve Long64/Compat32.
Existing legacy helpers serve both profiles. Compact `LoopCx` is shared by Direct paths with a
statically word-sized count and an in-limit target; compact and general handlers call the same
width-aware algorithm. The alias's accepted forms and block boundaries remain; dispatchers and walks
are separate. Opaque helpers keep the Machine walk for evidence/context handoff.

The prefix, segment-push, far-branch and indirect CALL/JMP exclusions are gone. Remaining
`shared_instruction` restrictions have these model facts:

| Restriction | Model fact |
|---|---|
| More than ten instruction bytes | Alias keeps the 286 limit; I386 allows fifteen (80286 PRM App. C item 10 p. C-2; 80386 PRM §14.7 item 6 p. 14-6). |
| Sequential end at 10000h | Alias wraps IP; Machine checks EIP against CS (80386 PRM §14.7 item 8 p. 14-6). |
| MOV CR/DR/TR | Frozen alias has no system-register personality. |
| Dword Jcc | Alias keeps conditional-branch IP truncation; Machine checks full EIP (SDM Vol 2A §3.3 Jcc); outside these families. |
| String source FS/GS or SS | Alias lacks ordinary-string FS/GS selection and keeps the 286 #GP limit rule; I386 distinguishes #SS (80386 PRM §14.7 item 7 p. 14-6). |

The family allowlist still excludes system/numeric dispatch outside the shared scalar/string/unified
families. No unified family retains a mnemonic exclusion.

### Alias policy and witnesses — READ / MEASURED

Decision-23 §6 freezes the superset decoder, ten-byte limit, selector bases, MOV CS #UD,
word-at-FFFFh faults, in-guest delivery, no A20 and the 286 real FLAGS image. POPF/IRET clear
IOPL/NT on the alias; I386 restores its documented image (80286 PRM App. B POPF p. B-86, §5.3 Table
5-3 p. 5-7; 80386 PRM §17 POPF p. 17-130; SDM Vol 3B §25.17.2). These are model expectations, not
conflicts.

The §6 amendment accepts manual behavior within the unified families: the xj-5t9 operand-size forms;
XLAT address size and FS/GS overrides; SP wrap and whole-operand limits; POP using SP with high ESP
bits retained; whole far-frame preflight and deferred CALL/IRET commits; POPA skipping its discarded
SP slot. Word LDS/LES and BOUND with a 67h memory operand now check the **full offset** against the
alias limit, because they belong to the unified families. I286 Machine still rejects unavailable
operand-size forms; I386 is unchanged. The alias still exits on LSS/LFS/LGS and PUSHAD/POPAD through
its accepted-form boundary; Machine I386 executes them. Stack-limit faults use vector 13 on I286
real mode/alias and 12 on I386; protected stack violations use #SS(0). Direct witnesses in
`legacy_u3_review` cite SDM Vol 2A §3.3, Vol 2B §4.3, 80386 PRM §§9.1, 17.1.3, and 80286 PRM App. B
POPA p. B-85.

Outside the unified families, `SegLimitCheck::alias_low16` names the frozen ordinary-data quirk:
only the limit gate masks to 16 bits; the load/store keeps its full linear address. The single
interpreter policy point cites §6 and is consulted only when the full-offset gate fails.
Machine/unified gates use full offsets. Ordinary FS/GS MOVs retain the parent selection behavior.

`application_conflict` always returns `None`; the parity allowlist is empty. Independent
`conflict_expectation` values check both paths for segment pushes/pops, immediate dword PUSH,
near/far dword returns, dword LDS/LES, ENTERD/LEAVED, ECX LOOPcc, dword relative/indirect CALL and
indirect JMP (SDM Vol 2A §3.3, Vol 2B §4.3; 80386 PRM §§17.1.2–17.1.3 pp. 17-1–17-2).
Direct/forced-Checked parity covers these widths, SP=0/FFFFh, far frames, ENTER/LEAVE and device
reads; focused witnesses check cache/A20 independence, FLAGS, self-modification, normalized IR and
raw-proof revalidation.

The parent-compatibility table has **18 cases** with fixed GPRs, FLAGS, selectors, IP, memory, steps
and retirements: ordinary 66h/67h ALU/MOV/string forms, segment overrides, and conventional
PUSH/POP/LEAVE/PUSHF. Expectations are hand-evaluated from `24a97d0`'s `lower_read`, `with_segment`,
scalar ALU/register writes, `exec_rep_string_real` and stack handlers, independently of current-path
parity. The 67h moffs row is `67 A1 00 00 01 00`, DS=0, with 1234h at linear 10000h: parent
`effective_address_no_segment` keeps disp32=10000h, `SegLimitCheck` tests `(10000h & FFFFh)+2`, the
load reads linear 10000h, and AX becomes 1234h while upper EAX is preserved. These expectations
describe parent compatibility.

### Restart snapshots and fault evidence — READ / MEASURED

Unified scalar alias reads use the Machine ledger in retry-specialized walks; ordinary alias loads
keep their completion policy. LDS/LES, POP-to-memory and multi-read frame helpers retain each
answered transfer until one retirement. POPA/POPAD and PUSHA/PUSHAD preflight the complete frame
before any device access. ENTER stages display values before frame writes and retains completed
RAM/device displays across retries; completion clears snapshots even at the same IP.

Between an MMIO exit and resume, edits preserving ENTER's architectural inputs at their read
widths retain the attempt so no acknowledged transfer repeats; changing an input restarts ENTER.
BP/EBP is read at operand size for the initial push and, only when nesting reads displays, at stack
size for addressing; identity uses the wider applicable width. SP/ESP is read at stack size for
addressing and operand size for FrameTemp, so identity uses the wider width (SDM Vol 2A §3.3 ENTER).
Effective SS base/limit are 32-bit values (Direct uses selector<<4 and FFFFh); SS.B selects 16/32-bit
stack size. The effective limit rule and Checked read/write permissions participate as used. Identity
also includes operand size, the effective A20 boolean (always enabled for alias helpers), allocation
imm16, and nesting imm8 modulo 32. Unread GPR/segment bits do not participate. CS:IP owns the ledger.

Two identity slots retain these values exactly, without hashing. They become the first two completed
display snapshots; identity remains in unused key/high-value bits. Each snapshot retains its ordinal,
value and device-answer byte boundaries. The retained BP/EBP, SS base, stack size and operand size
determine its address. Before collection, an identity mismatch abandons all snapshots, raw answers,
frame acknowledgements and pending completions. The earlier exit owns its device evidence. This
also covers incomplete displays and attempts with no display reads. FrameTemp behavior is unchanged.

The fault-only helper-ledger projection strips visits/write tags, suppresses internal identities and
snapshots, and expands display provenance into the original bus-address/value pairs. Its shared-walk
caller selects actual legacy helper IR; ordinary scalar/vector instructions export their original
ledger keys, including alias linear addresses above FFFFFFFFh. Its dedicated legacy instruction-walk
caller projects that walk's helper keys after either scalar or opaque fault analysis. Witnesses cover
alias, Machine Direct and Checked ENTER, far CALL/RET, IRET, POPA, LDS and BOUND faults, plus ordinary
MOVDQU with an acknowledged read at 1_0000_0000h. Non-ENTER helper faults now report completed
device reads, where the parent reported none.

Only the current attempt is retained. Before two displays complete, two identity slots plus at most
four byte answers need six slots. Later collection peaks at 29 snapshots plus four answers (**33**).
Zero/one-display attempts retain two identities and at most four write parts (six). Otherwise the two
identity slots are already among the 30 snapshots; 32 frame writes, or 33 when one crosses an
A20/32-bit bus boundary, give **63 of 64** slots. No phase reaches the ledger's release overflow drop.
Maximum-nesting witnesses, including abandoned attempts, run in debug and release. Other witnesses
cover overlapping EBP edits, ignored upper register bits, ESP FrameTemp edits, word/dword stacks,
SS limit/allocation edits, BP/SP/SS/A20 edits, device-page splits, and 65 frame-only input edits.
Only ENTER executes identity checks and snapshot collection/lookup; projection runs on faults.

### Decode design and identity — READ

`model/decode.rs` contains the explicit encoding membership table (one bit per
current model), compiled to a constant-time code-indexed array. Decoder feature
tags no longer decide Machine membership. Each `DecodeSet` owns decoder options,
its segment-prefix policy, and the absent-encoding result. `DecodeAction` separates
a defined instruction, a canonical alias, and absence: `Some(vector)` emits a
fault, `None` returns a lift refusal which becomes `Exit::UnknownInstruction`.
Both current entries select vector 6; neither uses the refusal policy. This
provides the C2 policy without creating an 8086 model or guessing its encodings.
The incremental 286 rejection is shared by fetching and lifting, preserving
fault priority before later bytes or coprocessor gates are examined.

SDM Vol 3B §25.15 pp.25-5–6 licenses canonical 82h group-1, group-2 /6 and
group-3 /1 aliases. The existing accepted aliases retain their results. Reserved
`UD0`/`UD2`, later NOPs and identity instructions are absent from the explicit
sets; `UD1` is now absent too. The 80386 PRM Appendix A two-byte opcode map
p.A-7 leaves 0F B9 undefined, and §14.6 Table14-1 p.14-5 requires #UD at the
faulting instruction. This fixes the baseline's I80386 refusal. Existing
reserved LOADALL/XBTS/IBTS slots continue to fault; the table does not admit them.
The older unsupported coprocessor pairing policy is preserved (decision-25).

**MEASURED mechanism:**
- *`ip-boundary-1` is a layout effect, not NEC code.* 060d446a already
  has the shape the f15060b9 campaign blamed on C4a. In `Vcpu::run_steps` and
  `run_direct20`, `RunGuard::finish` is inlined, while
  `LocalKey::with::<RunGuard::finish closure>` and the `time_stats::LOCAL`
  accessor shim are called out of line, three times in `run_steps` (objdump
  call lists). The C4a tree has the f15060b9 shape: `RunGuard::finish` is one
  call, and the TLS access is inlined inside it. The shape follows rustc's
  codegen-unit partition of x86jit-core. In 060d446a the `LocalKey::with`
  closures of `RunGuard::{enter, finish}`, `RunGuard::drop` and
  `dispatch_counts` are in a different CGU from `RunGuard` itself. In C4a they
  are in the same CGU (see the partition bullet below).
- *Partition (diagnostic `-Zprint-mono-items`, x86jit-core only; profile
  unchanged).* In 060d446a, `memory::Memory` shares a CGU with the
  `std::collections::BTreeMap` generic instances. In C4a those instances move
  to the CGU of the B-tree node code, and the `std::thread::LocalKey`
  instances move in with `memory::Memory`. The `RwLockWriteGuard` drops of the
  shared dispatch map move from another CGU into the one that holds
  `cache::TranslationCache`. The result in `real16_loops`:
  - `Memory::refresh_code_aliases` shrinks from 3,368 to 1,544 bytes, with
    B-tree entry inserts out of line;
  - two `TranslationCache::insert_checked` instances (the closures of
    `vm::finish_single` and `vm::legacy::resolve_direct_uncached`) shrink from
    4,488 and 4,544 bytes to 1,648 and 1,712, with `DispatchMapWrite` and
    `RwLockWriteGuard` drop glue out of line;
  - `invalidate_range` for SMC shrinks from 5,172 to 3,704 bytes.

  These run on every SMC re-lift through the shared cache, which the alias
  and I8088/I8086 use and the I286/I386 private interpreter cache does not
  (READ, `Vcpu::run_steps` docs). C4a does not change these functions
  (READ, diff).
- *What moves the partition* (diagnostic, 060d446a's core with parts of C4a

  - those types plus the `Exit::I8080Mode` variant: the C4a partition, with
    either the folded `from_exit` arm or a panicking one.

  The public variant itself moves rustc's CGU merge. Neither the
  `#[inline(never)]` nor a trial that moved the BRKEM scan out of the

## Split off the hot path (xj-ir6.31)

Gate base: a373f11b (main after C4a) with 060d446a reverted, code only — main
without the split. The first round measured against f15060b9, before C4a landed;
it is kept below as history.

### Change — READ

- The scalar and wide transfers in `memory.rs` are containment-only, with the
  bodies they had before xj-ir6.12. The walk's providers (`RunningMemory`,
  `ChildMemory`) return the containment miss unchanged. An associated constant,
  `InterpreterMemory::SPLIT`, is false for them, so their `vstore` compiles no split
  branch.
- A data access over adjacent RAM/ROM regions first ends with the usual
  `UnmappedMemory` exit, with no register of that instruction committed. The code that
  already handles that exit calls a cold, non-inlined function: the application and
  alias dispatchers' exit arms (`vm/legacy.rs`), `execute_shared` on the I286 and
  I386 Machine path (`interp/legacy.rs`), and `interpret_block_mode` for `step_one`
  and `interpret_block` (`interp/mod.rs`).
- That function walks the rest of the block again, from the faulting instruction,
  through the existing retry walk. The retry walk's provider, `SplitMemory`, performs
  the span with the out-of-line functions that xj-ir6.12 added. Re-execution is
  restart-safe because a fault exit leaves the instruction's registers uncommitted
  (spec.md §16; SDM Vol 3A §§7.5-7.6), and stores made before the miss are made
  again with the same values. The real-mode stack-frame helpers
  (`interp/control.rs`: interrupt delivery, far CALL/RET, IRET, PUSHA/POPA, ENTER,
  PUSHF/POPF) commit SP word by word, so they perform the span themselves
  (`read_across_regions` / `write_across_regions`), exactly as the walk did before
  this change. The rest of the block ends where the block ends, so retirement, step
  and block accounting equal one walk of the block.
- If the re-execution stops at the same access without completing an instruction,
  with a guest-map containment miss of its own (a gap, a Trap byte or a LOCK
  operand), the first exit is returned with its evidence. Any other exit there, such
  as a host fault at the operand's first byte, is the re-execution's.
- Out-of-walk callers use `Memory`: JIT fallback helpers, Machine bus helpers, x87
  memory operands and user copy. Its public accessors try containment first and call
  the cold span function only on a miss. A 16-byte `vstore` through `Memory` or
  `SplitMemory` goes to the out-of-line `vstore16_split`, which keeps the review fix:
  both transfers are checked before either is written.
- A one-byte access lies in one region or in none, so the scalar `*_spanning`
  entry points call the span functions only for a wider access. The twenty-bit
  walk (I8088, I8086, V20, V30) moves every data byte through a one-byte transfer
  (`interp/i8086.rs`; `lift/i8086.rs` lowers loads, stores and strings to its
  Wrapped primitives), so no containment miss over adjacent regions reaches it:
  `execute_shared20` keeps its shape without the re-execution, and its byte helpers
  keep their containment-only shape.

### Review fixes after the rebase round — MEASURED / READ

A review of the rebase-round tree found two regressions against 060d446a. Both
are fixed; behaviour equals 060d446a again (MEASURED).

- Real-mode interrupt delivery in the walk committed SP after each frame word. A
  CS or IP word over two adjacent RAM regions missed after FLAGS was pushed, and
  the re-execution pushed a second frame lower (Alias, INT n and INT3). The frame
  helpers now perform such a span themselves (`read_across_regions` /
  `write_across_regions` in `control::push16`, `pop16`, the ENTER display read and
  the IVT reads), as the walk did at 060d446a. The reviewer's alternative (store
  all three words, then commit SP once) would change the exit state of a frame
  that meets a gap part-way, so it was not taken.
- When the re-execution stopped at the first attempt's address with a host fault
  (the operand's first byte host-protected), the first attempt's guest-map exit
  was returned. The first exit is now kept only when the re-execution's exit is
  itself a guest-map containment miss; otherwise the re-execution's exit, with its
  HostAccess evidence, is returned.

Evidence (MEASURED): scratch harnesses compared main at 6614d2e0, which carries
060d446a, with this tree. They covered INT 21h, INT3, far CALL, PUSHA, ENTER,
PUSHF, IRET, RETF, POPA and POPF on Alias, I286, I386, I8086 and V30, under `run`
and `run_steps`, with every frame word in turn meeting the edge. Layouts:
contained, RAM|RAM, gap on either side, Trap on either side, ROM on either side,
an IVT entry over a RAM|RAM edge, a gap or a Trap byte, and a host-protected page
part-way through the frame (contained and over a region edge at three offsets).
All 10,200 + 2,560 outcomes are equal, including exit, fault metadata, SP and the
other registers, flags, frame bytes, retirement and step counts. Host addresses
were normalised.

New permanent witnesses: in `cross_region_ram.rs`, module `reexecution`, an INT
frame, every stack-frame helper, Real16 block accounting (a mid-block split and
REP MOVSW, `run_steps` budgets 1–9) and Long64 block accounting (mid-block scalar
and 16-byte splits on every tier, with and without the Trap window); in
`cross_region_host_fault.rs`, a protected first byte (load and store, every tier,
as the first instruction and after an INC). With the two fixes reverted, the INT
frame and the protected first-byte witnesses fail; the others pass on both
