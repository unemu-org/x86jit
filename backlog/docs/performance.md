## Tiering — wall-clock by mode

`eager` compiles every block on first execution; `tier` interprets a block until it is hot (50 runs) then compiles it inline; `bg` compiles hot blocks on a worker thread (`x86jit-run` ships `tier`); `region-bg` (BGT-6, opt-in) tiers a hot loop up to a background-compiled superblock region — a win only on long multi-block warm loops (`hotloop`), a loss on one-shot workloads. `best↓` is the fastest mode's speedup over `eager`.

## Machine-path baseline (decision-23 U0)

Measured on 2026-11-11, 21:28:44–21:31:59 UTC, with engine commit
`0eb0d06d54aa196a8a26c2cdacc0a98b67e68172` and the U0 benchmark changes in the
working tree. **No engine change or optimisation.** Host: Apple M5 Pro, 18 CPU
cores (6 Super and 12 Performance), aarch64, macOS 27.0.1 (26A434), Darwin 27.0.0.
Compiler: rustc 1.98.1 (48a229cea 2026-09-01), release profile, default features.
The linker explicitly used the installed macOS 14.4 SDK because the default
linker rejected the macOS 27 SDK's text stubs.

Eight rounds per workload, four paths interleaved in rotating order. Every path
occupies each position twice. Each sample uses a fresh VM and vCPU, followed by
warm-up outside both measurement windows. The divisor is 5: warm-up is 200,000
steps, except `straight-line`, which always warms one full 30,592-step traversal
and measures three more (91,776 steps). VM construction, program/data loading,
cache fillers, state comparisons and reporting are excluded. The counter window
includes the two clock reads and counter-call overhead; no overhead is subtracted.
Wall time brackets only the measured step runner. All paths use the same runner.

`Application` is today's `set_cpu_mode(CpuMode::Real16)` path (the future alias).
`I286` and `I386` select `ExecutionProfile::LegacySystem` through
`set_legacy_cpu_model(LegacyCpuModel { generation, model_semantics_id })`, with
A20 enabled. `I286 A20 off` also calls `Vcpu::set_a20_enabled(false)`. Ordinary
hidden segment caches are seeded with `CpuState::legacy_real_entry` after setting
the selectors; changing visible selectors alone does not configure those caches.
Code, data and stack addresses stay below 1 MiB on every workload.

Every sample asserts budget exhaustion and its exact returned step count. Warm-up
and measured `retired_instructions()` counts, and final GPRs, IP, six segment
selectors, FS/GS bases, flags, vector/opmask registers, x87 registers/environment
and MXCSR, agree across all four paths and all eight rounds. All 480 samples
passed. The denominator is a `run_steps` guest unit: one completed instruction or
REP iteration. The separate completed-instruction counts below therefore differ
from steps for `dos-mixed` and `rep-movsw`.

The short probes are repeatable loops: `ip-boundary-{1,64}` branches before the
segment end instead of depending on sequential IP wrap, which is not shared
behaviour across these paths; `smc-next-{1,64}` patches the next instruction and
branches back instead of halting. The suffix is the run_steps slice budget.
`dos-mixed` retains rotating slice budgets 1/7/64/256/1024. The former cold
straight-line pass is warm-up; keeping its original four traversals also avoids
letting SI reach a segment-crossing word access. The dense-code probe retains
1,024 synthetic entries in the shared Application cache on every path; this is
not a claim that the separate legacy per-vCPU cache has the same fillers.

No builds or tests ran alongside the measurements. Process inspection (`ps`) was
blocked by the sandbox, so absence of other heavy host jobs could not be verified.
A load spike was allowed to subside before this run. `nice -n 10` was attempted,
but the sandbox rejected `setpriority`; the benchmark consequently ran at its
inherited priority. Load averages (1/5/15 minutes) were **7.63/9.58/9.75** at the
start and **9.18/7.94/8.91** at the end. The 120 pre-round readings ranged over
**3.01–10.96 / 6.72–9.58 / 8.52–9.75**. These are shared-host measurements;
retain the reported wall-time ranges when assessing the +2% wall gate.

The main U2 input is the size of the legacy cost: I286 uses **7.84×** the host
instructions of Application on `alu`, **6.71×** on `dos-mixed`, and **19.33×** on
`rep-movsw`; wall costs are **9.09×**, **6.99×**, and **21.70×**, respectively.
I386 is somewhat cheaper than I286 but remains far above the Direct-class +2%
target. Disabling A20 adds at most **0.17%** to I286's median instruction count
on these below-1-MiB workloads. SMC reverses the direction: legacy paths use
42–58% fewer instructions and 53–65% less wall time than Application. These are
measurements of the existing dispatchers, without attributing the gap to any
one internal operation.

These numbers establish the pre-unification Application and LegacySystem
baselines for decision-23: the alias's +0.5% per-loop instruction gate, its
`dos-mixed` +2% wall gate, the Machine-versus-alias +2% gate, the eventual alias
switch, and the unchanged-level-1 requirement when optional timing lands. Future
comparisons must use this same harness, host, build settings and sample sizes.
I8088 and level-2 overhead await those implementations. Application
Long64/Compat32 engine code is untouched; its emitted-code witness remains the
separate gate specified by the decision.
